# Slicer installer scripts

Two kinds of script live here.

## Outer installers — not installed into the package

| File | Used as |
| ---- | ------- |
| `install.sh` | `curl -fsSL https://download.slicer.org/install.sh \| sh` — Linux and macOS |
| `install.ps1` | `powershell -c "irm https://download.slicer.org/install.ps1 \| iex"` — Windows |

They install Slicer onto a machine that does not have it yet, so there is
nothing for them to be installed *into*: they are source only. download.slicer.org
redirects those two URLs to the copies on this repository's `main` branch, so a
change merged here is what users get. `CMakeLists.txt` deliberately does not
install them.

Being piped into a shell, they take no arguments: every option is an
environment variable, and [`ENVIRONMENT.md`](ENVIRONMENT.md) documents them all.
A change to what either installer reads, or to how it behaves, belongs there
too.

## Inner scripts — installed into the package

| File | Platform | What it does |
| ---- | -------- | ------------ |
| `slicer-language` | Linux, macOS | `list` prints the available interface languages; a code like `es-419` installs it and switches Slicer to it |
| `slicer-language.ps1` | Windows | The same |
| `slicer-deps` | Linux | Prints the package-manager command for the system libraries Slicer needs; `--install` runs it |
| `slicer-shortcuts` | Linux, macOS | Adds a desktop icon and pins Slicer to the dock; `--desktop` or `--dock` for just one, `--remove` to undo |
| `slicer-shortcuts.ps1` | Windows | Adds a desktop shortcut, and shows how to pin Slicer to the taskbar, which Windows lets only the user do; `-Remove` to undo |

These do the things that are *not* installing Slicer, and are run by the user
afterwards. `CMakeLists.txt` copies them into `bin/` in the build tree and
installs them into `${Slicer_INSTALL_BIN_DIR}`, so each one finds the Slicer
launcher relative to its own path and needs no configuration.

`slicer-deps` is separate precisely because installing distribution packages
needs root: the installer itself never asks for it and only ever writes under
`$HOME`.

On Windows, run the `.ps1` scripts with
`powershell -ExecutionPolicy Bypass -File <path>`: the default execution policy
of client Windows blocks running a `.ps1` file by name.

## Generated copies

Three things here are copies, generated by `tools/sync-embedded.sh`:

```
deps/*.txt  ->  slicer-deps           ->  install.sh
                slicer-language       ->  install.sh
                slicer-shortcuts      ->  install.sh
                slicer-language.ps1   ->  install.ps1
                slicer-shortcuts.ps1  ->  install.ps1
```

- `slicer-deps` carries the package lists of [`deps/`](deps/), because it runs
  from an installed package, where `deps/` does not exist.
- `install.sh` and `install.ps1` carry every inner script, because they run on
  machines with no Slicer yet and must be able to set up a package that
  predates this directory. They write them out **only when the installed
  package does not already contain them**, so once these scripts ship in the
  package, the package's own copies win and the embedded ones are never used.

So to change which system libraries Slicer needs, or an inner script: edit
`deps/*.txt` or the script, run

```sh
Utilities/Scripts/SlicerInstallers/tools/sync-embedded.sh
```

and commit the regenerated files together with your change. Never edit the
generated blocks (between the `BEGIN/END generated` markers) by hand.

Two checks catch a forgotten regeneration:

- the `CI (Installer Scripts)` workflow runs on every pull request that touches
  this directory, and fails with a diff of what to regenerate;
- the `slicer-installers-embedded-copies-test` CTest runs the same comparison
  (`CheckEmbeddedCopies.cmake`) on every platform.

## Provenance

These scripts were developed in <https://github.com/mauigna06/slicer-installer>,
which now mirrors this directory: this is the canonical copy. That repository
keeps the inner scripts in `inner/`, which is why some comments in the
installers mention that path; `tools/sync-embedded.sh` runs unchanged in both
layouts.
