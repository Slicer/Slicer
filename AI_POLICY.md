# AI Policy

Slicer is a project whose contributions are expected to originate with humans. AI assistance is allowed under the guidelines below.
Generative AI is not just another tool, and as such special guidelines should be used when using it.
Note that the general contribution guidelines in [CONTRIBUTING.md](CONTRIBUTING.md) still apply.

When using generative AI in the context of the Slicer project, keep in mind the following principles:

- Understanding: Always review what you generate as if you wrote it yourself
- Accountability: Always assume responsibility for what you share and commit, even when AI generated
- Transparency: Always disclose when and how you are using generative AI
- Respect for reviewer/maintainer time

## For contributors

1. When committing, use your own name or alias and do not add an AI tool as a co-author, and follow the [commit message guidelines](CONTRIBUTING.md#how-to-write-commit-messages-)
2. When creating a pull request, disclose when and how you are using AI using the PR template
3. When running CI on unreviewed AI-generated pull requests, use draft status and write in the description that it is yet to be reviewed
4. Before asking for any review, review everything yourself and ensure everything is understood and done the right way
5. Always separate your contributions into different parts and merge them iteratively or separately to reduce the quantity of changes to aid review, with a goal of a maximum 1k lines change by pull request
6. Always ensure generated comments, documentation and release notes are concise, so that it is comfortable to read for humans
7. If anything is unclear, not understood yet or too verbose, rework the generated code yourself until it is clearer and before asking for an actual review
8. When asked about code behavior during the review, do not copy and paste AI output, but answer questions yourself as you already know the answer as per above guideline

## For reviewers

1. If a contribution does not follow our contribution guidelines, please reference the relevant guidelines and request that they be addressed before a review can begin
2. If a contributor explicitly declines to make the requested changes or follow the guidelines, invite a maintainer to help resolve the issue
3. You are free to ask any questions about how the code works and the contributor is expected to answer without copy-pasting AI
4. You are free to ask the contributor to make comments and documentation leaner and more readable
5. Do not approve a pull request unless you have actually reviewed and understood the code; when only acknowledging a pull request, submit a comment instead of an approval
6. By reviewing and approving a change, you take on responsibility for its code quality and design choices
